# Agent Note: 重新执行已失败或已取消的 Task Run

Status: implemented

[English](2026-10-08-restart-stopped-task-run.md) | 中文

## Problem

已失败或已取消的普通 Run 是终态：它的 Session 已关闭，清理已删除它的文件，业务键的预留也已结束。人在 Run 页面上看到它停止后，只能等插件再次派发该业务对象，而对已处理过的内容不再派发的轮询插件永远不会这样做。由轮询再次派发会重做人可能有意结束的工作，而且没有人提出过这个要求。

## Decision

`restart` 命令（`POST /runs/{runId}/restart`，操作 `restartRun`）为已失败或已取消的普通 Run 的业务键预留一个新的普通 Run，并以状态 201 返回它。新 Run 报告 `restartedFrom`，即停止的 Run 的标识。它的输入是停止的 Run 最近观察到的输入，并使用定义当前的配置、表单和代码版本。停止的 Run 不变。

只有停止的 Run 是其业务键最新的普通 Run，且其定义已安装并启用时，命令才会成功，否则以 `invalid_state` 失败。其他类型或状态的 Run 一律被拒绝，包括仍在结算或清理受阻的 Run。相同的请求与其他命令一样重放最初的结果。

引擎不决定新 Run 从哪里继续。能够接续的插件通过 `restartedFrom` 读取停止的 Run 并采用其检查点；不能接续的插件从输入重新开始。Task Web 在已停止的 Run 的结果页提供该操作，在业务键已有更新的 Run 时链接到它，并在执行面板显示 `restartedFrom`。

## Alternatives considered

**重新打开停止的 Run。** 否决：终态 Run 不可变，它的 Session 已关闭，资源已释放。重新打开需要为每个状态增加第二套生命周期，并会改写该次停止的审计记录。

**由轮询插件派发后续任务。** 否决：轮询无法区分失败与人主动结束的任务，并在没有人提出要求时重做工作。想再次执行的人在正在阅读的 Run 上点一次操作即可。

**由引擎复制停止的 Run 的检查点。** 否决：检查点是插件的私有数据，可能引用清理已经删除的文件。只有插件知道要恢复什么、哪个阶段可以安全重复。

**允许重新执行业务键下任意已停止的 Run。** 否决：业务键下较旧的 Run 会在更新的 Run 旁边开出第二条工作线，而业务键同一时刻只允许一个未结束的 Run。只重新执行最新的 Run，每个业务对象只保留一条工作线。

## Consequences

人可以在 Run 页面上继续已停止的业务对象，不需要修改插件配置。需要比“从输入重新开始”做得更多的插件，必须自己读取 `restartedFrom`。新 Run 从最近观察到的输入开始，因此停止后发生变化的业务对象会按其最新内容重新执行。本次变更之前写入的 Task 数据库记录，其 `restartedFrom` 读作 `null`。
